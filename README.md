# Linux Security Hardening Checklist

Practical Linux security hardening checklist focused on real-world administration, infrastructure security and hands-on security lab usage.

This repository is part of my cybersecurity learning and documentation path, combining 20+ years of infrastructure experience with practical security engineering, Linux hardening and vulnerability reduction.

## Focus Areas

- SSH hardening
- User and permission management
- Firewall basics
- Logging and monitoring
- Patch and update management
- Service reduction and attack surface minimization
- Backup and recovery considerations
- Basic Linux security commands

## Structure

| File | Topic |
|---|---|
| `01-ssh-hardening.md` | SSH configuration and access control |
| `02-user-permissions.md` | Users, groups, sudo and permissions |
| `03-firewall-basics.md` | Basic firewall and network exposure controls |
| `04-logging-monitoring.md` | Logs, monitoring and audit basics |
| `05-patch-management.md` | Updates, patching and package hygiene |
| `06-services-attack-surface.md` | Reducing exposed services and attack surface |
| `07-backup-recovery.md` | Backup and recovery security considerations |
| `08-basic-linux-security-commands.md` | Useful Linux security commands |

## Goal

The goal is not to create a universal hardening standard, but a practical checklist for administrators and security learners who want to understand Linux systems from a security perspective.

Security is not only about tools.  
It is about understanding systems, configurations, assumptions, weaknesses and real attack paths.

## Disclaimer

This checklist is for educational and defensive security purposes only.  
Always test changes in a lab or staging environment before applying them to production systems.
